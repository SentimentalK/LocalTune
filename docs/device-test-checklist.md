## 已知限制

- iOS Safari 与 Firefox 不支持 `showDirectoryPicker`（File System Access 目录选择）。v1 只在 Android Chrome 与桌面 Chrome 验证；其它浏览器不承诺可用。
- 后台播放与自动切歌受系统省电策略影响（Doze、电池优化、厂商 ROM 的后台清理）。同一现象在不同机型上可能不同，需按设备分别记录。
- 结论必须区分两件事：
  - **音频继续播放**：`<audio>` 出声、进度推进。
  - **JS 自动切歌**：自然播完后由页面逻辑执行下一首。
  页面被冻结/挂起时前者可能成立而后者不成立，不要合并为一句话结论。
- 音频通过 object URL 播放；文件权限被撤销后，已加载的当前曲可能继续出声，但加载新曲会失败。这属于预期行为，需与「授权丢失」分开记录。
- SPA 的 OneDrive refresh token 24 小时过期：App 启动时会尝试一次静默重授权（顶层跳转）；失败则来源显示「需要重新登录」，已缓存曲目仍可播放。
- `@microsoft.graph.downloadUrl` 分钟级~1 小时失效：播放失败会自动重取一次；连续失败需重试或重新登录。

## 记录方式

- 结果三态，只填一种：
  - **通过**：预期全部满足。
  - **失败**：任一预期不满足，且可复现；必须附证据。
  - **阻塞**：因环境缺失（无蓝牙设备、无法部署新版本等）无法执行；在备注写明缺失项。
- 失败必须附至少一项证据：
  - `chrome://media-internals` 中对应的播放器/session 记录（含错误码、事件时间点）；
  - 或录屏片段（标明时间点与操作）；
  - 证据放在备注列（粘贴关键行或链接），不要只写「不行」。
- 每条同时记录设备与构建版本（见「测试环境记录」），跨版本对比时另起一行。
